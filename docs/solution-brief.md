# AI Presales Copilot：制造业设备运维方案售前工作台

## 一句话定位

这是一个面向制造业售前场景的可复现作品集：把客户需求、企业知识、Agent 方案编排、POC 验收、模型部署选型和 LoRA/QLoRA 实验串成一条可审计的交付链路。本项目负责“售前如何设计和验收方案”；现场工程师的终端问答由独立项目负责。

## 客户问题

客户希望建设制造业设备运维 AI 能力，但维修手册、报警说明、点检规范和历史工单分散在 PDF、表格和系统中。售前需要先回答方案是否可行、如何验收以及如何部署，并处理三个典型约束：

1. 数据可能不能出域，需要比较云端 API、本地量化服务和 GPU 集群。
2. 回答必须能追溯到资料版本，不能把模型记忆当成产品事实。
3. 需要先做一个可验收的 POC，再决定是否投入微调、GPU 和生产运维。

## 售前用户与决策人

| 角色 | 关心的问题 | 作品集中的证据 |
|---|---|---|
| 售前/方案架构师 | 如何把客户需求变成可交付方案 | 需求结构化、架构、POC 和风险门 |
| 业务负责人 | 是否能减少检索和诊断时间 | 黄金问题集、POC exit criteria |
| IT/架构师 | 如何接入现有系统、是否可私有化 | API、部署矩阵、容量输入 |
| 安全/法务 | 数据驻留、权限、审计、敏感信息 | 风险门、脱敏检查、红队用例 |
| 采购/管理层 | 投入、周期、可扩展性 | TCO 假设、分阶段路线图 |

## 业务成功指标

作品集只把指标定义为“待实测目标”，不把合成数据的结果包装成客户生产承诺：

- 业务质量：黄金问题集上的答案可用率、引用正确率、拒答/追问正确率。
- 检索质量：召回覆盖、引用完整度、版本/权限过滤正确率。
- Agent 质量：结构化输出通过率、工具参数错误率、高风险审核触发率。
- 体验质量：TTFT、完整答案延迟 p50/p95、错误率。
- 工程质量：CPU RSS、GPU VRAM、吞吐、恢复时间和日志完整性。
- 商业质量：数据边界、模型成本、硬件成本、运维责任和上线周期是否可解释。

## 非目标

- 不用合成客户资料证明生产 SLA、准确率、认证或法律合规。
- 不把 0.5B 本地模型的中文质量当作企业生产模型质量。
- 不在训练集里放客户隐私、真实账号、密钥或未经授权的受版权保护资料。
- 不让 Agent 直接修改生产系统、发送客户邮件或执行不可逆操作。
- 不实现一线工程师的终端问答体验；该能力属于独立的 Industrial Maintenance Assistant 项目。

## 交付叙事

```
客户约束
  -> 需求结构化与缺口识别
  -> 带版本/来源的知识检索
  -> Agent 生成架构与 POC
  -> 模型策略：RAG / Prompt / LoRA / 服务形态
  -> 证据、敏感信息与风险校验
  -> 人工审核或结构化交付
```

这条叙事体现的不是“模型会回答问题”，而是售前需要的判断力：哪些结论有证据、哪些需要实测、哪些必须交给人审批。
