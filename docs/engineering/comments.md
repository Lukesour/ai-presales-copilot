# 注释与 Docstring 规范

## 目的

注释只保留代码、类型和测试无法稳定表达的原因。重点说明所有权、不变量、安全、兼容边界、并发、重试、隐私或失败语义，不复述语法。

## 语言

治理、任务和产品文档使用中文。源代码注释、Docstring 和公共 API 描述默认使用英文，确保边界含义可被工具和跨语言协作者检索。

## 需要注释的情况

- 不明显的确定性策略或不变量；
- 类型无法表达完整前置条件或失败语义的公共边界；
- 重试、幂等、取消、顺序、原子性或并发假设；
- 鉴权、隐私、凭据处理和留存决策；
- 数据库或 checkpoint 迁移顺序；
- Replay、fixture 和实时 API 的有意差异；
- 局部 lint/type-check 抑制及其原因；
- 带任务 ID 和关闭条件的可执行 TODO。

如果更强的名称、类型或可执行测试可以完整表达规则，优先改它们，不增加注释。

## 禁止的注释

拒绝以下内容：

- 复述下一行代码或函数名；
- 保留注释代码或调试指令；
- 记录 Git 已经拥有的完成历史；
- 声明测试没有校验的行为；
- 复制权威文档全文；
- 承诺没有责任人和关闭条件的未来清理。

## 公共 API 描述

只说明适用事实：责任人、必填输入、校验边界、变更与原子性、返回/错误语义、取消/重试、生命周期约束和契约版本。不要把显而易见的 accessor 写成教程。

## TODO 与抑制

每个新 TODO/FIXME 必须包含稳定任务 ID、关闭条件和必要上下文：

```python
# TODO(CONTRACT-001): Remove the temporary snapshot comparison after the OpenAPI bundle
# becomes the only checked-in public contract.
```

抑制范围保持最小，并解释为什么不能采用更窄的修复。不得为了通过检查而抑制文件长度、不安全 cast、缺失类型或安全检查。

## Review 清单

- 注释是否提供了名称、类型和测试中没有的信息？
- 所述不变量是否被实现或验证？
- 是否写明了正确的责任边界？
- 重试、失败、隐私和兼容性描述是否准确？
- 已解决的 TODO、历史叙述和重复规则能否删除？
