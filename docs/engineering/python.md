# Python 工程规范

## 边界

- 领域策略、Pydantic 校验、模型调用、网络传输、持久化和 UI 组合保持不同责任；
- client、store、clock 和 model adapter 优先通过构造器注入；
- 确定性策略尽量保持纯函数，网络和文件系统副作用必须显式；
- Pydantic 模型不得静默编排检索、审核或持久化；
- 使用窄异常和可执行消息，不要在整个工作流外层盲捕 `Exception`。

## 运行时行为

- 远程调用必须有 timeout 和有界重试；
- 只重试瞬时错误，并在重试中保留幂等键；
- checkpoint 写入和 state-version 检查必须在持久化所有者内原子完成；
- 模型输出异常时 fail closed 或进入文档化审核路径，不得伪造模板响应；
- 凭据只从服务端环境读取，不返回 UI 或 trace；
- 异步/线程任务必须定义取消、所有权和清理行为。

## Pydantic 与类型

- 边界模型使用严格校验和显式默认值；
- 只有契约明确表示未知时才使用 optional，新流程不用哨兵字符串表示缺失；
- 公共线字段保持稳定，即使内部 Python 名称或实现类型变化；
- 只有责任清楚时才用 `TypedDict`、protocol 或窄 dataclass 表示内部状态；
- 公共边界避免 `Any`，无法避免的 provider payload 只能隔离在 adapter 内。

## 文件内聚

- 一个文件只有一个主要变更原因；
- 按行为或责任拆分，不能只按行数机械切分；
- 新手写 Python 文件目标为 300 个物理行以内；
- 既有超长文件首期只报告，后续拆分需有任务、责任人、依赖方向和保护测试。

## 依赖与脚本

- 新增依赖必须有原因、版本约束、许可和安全审查；
- 脚本应 import-safe，提供有类型的 `main() -> int`，使用显式路径并返回可执行错误；
- 检查命令默认不得改写仓库文件，名称明确为 `build`、`generate` 或 `export` 时除外；
- 生成命令必须提供只读 `--check` 模式供 CI 使用。
